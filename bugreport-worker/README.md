# گیرنده‌ی گزارش باگ (Cloudflare Worker)

برنامه گزارش را به این Worker می‌فرستد و Worker آن را به ربات تلگرام شما (متن، فایل تشخیصی، عکس‌ها) و اختیاری به یک Issue در GitHub می‌رساند. توکن‌ها فقط روی Worker هستند و داخل برنامه نیستند.

## چطور کار می‌کند

1. برنامه `GET /challenge` می‌زند و یک **پازل اثبات کار** (proof-of-work) می‌گیرد: پیدا کردن عددی که هش SHA-256 آن با تعداد مشخصی بیت صفر شروع شود. گوشی یا کامپیوتر کاربر حدود یک ثانیه کار می‌کند؛ ربات‌ها برای ارسال انبوه باید همین هزینه را بدهند.
2. برنامه `POST /report` می‌زند، گزارش + جواب پازل. Worker امضای پازل، انقضا (۱۰ دقیقه)، سختی و درستی جواب را چک می‌کند و هر پازل را فقط یک بار می‌پذیرد.
3. محدودیت‌ها: حداکثر ۹ مگابایت، ۳ عکس تا ۲ مگابایت، ۵ گزارش در ساعت برای هر IP، ۳۰۰ گزارش در روز.
4. Worker متن و عکس‌ها را به تلگرام می‌فرستد. اگر ارسال به تلگرام شکست بخورد، پاسخ ۵۰۲ می‌دهد و برنامه به کاربر پیشنهاد می‌دهد گزارش را به‌صورت فایل ذخیره کند.

### درباره‌ی کپچا

این کپچا Turnstile یا reCAPTCHA نیست؛ **اثبات کار** است. دلیل انتخابش: نیازی به لود کردن اسکریپت از سایت دیگر ندارد (در ایران `challenges.cloudflare.com` و مشابه آن ممکن است بسته باشد و فرم کاربر را قفل کند) و حریم خصوصی را حفظ می‌کند. نقطه‌ضعفش: «انسان‌بودن» را ثابت نمی‌کند، فقط ارسال انبوه را گران می‌کند. همراه با محدودیت IP و سقف روزانه برای یک ابزار گزارش باگ کافی است. اگر بعداً دیدید اسپم می‌آید، `DIFFICULTY` را به ۱۸ یا ۲۰ ببرید (هر ۲ بیت بیشتر، ۴ برابر کندتر) یا Turnstile اضافه می‌کنیم.

## راه‌اندازی (یک‌بار، حدود ۱۵ دقیقه)

پیش‌نیاز: Node.js، یک حساب Cloudflare (رایگان) و ربات تلگرام. (در ایران برای ورود به داشبورد Cloudflare و تلگرام معمولاً VPN لازم است.)

۱. **حساب و ابزار**
```bash
cd bugreport-worker
npx wrangler login
```

۲. **ربات تلگرام:** اگر ربات اعلان‌ها را دارید همان را استفاده کنید؛ وگرنه در تلگرام با `@BotFather` دستور `/newbot` بزنید و توکن را نگه دارید.

۳. **شناسه‌ی گفتگوی شما:** به ربات خودتان یک پیام بدهید، بعد در مرورگر این آدرس را باز کنید (به‌جای `TOKEN`، توکن ربات):
`https://api.telegram.org/botTOKEN/getUpdates`
در جواب `"chat":{"id":123456789` را پیدا کنید. این عدد `TELEGRAM_CHAT_ID` است. آن را در `wrangler.toml` به‌جای `REPLACE_WITH_YOUR_CHAT_ID` بنویسید.

۴. **فضای KV** (برای محدودیت‌ها و جلوگیری از استفاده‌ی دوباره‌ی پازل):
```bash
npx wrangler kv namespace create LIMITS
```
شناسه‌ای که چاپ می‌شود را در `wrangler.toml` به‌جای `REPLACE_WITH_THE_KV_ID` بگذارید.

۵. **رمزها** (هرکدام را می‌پرسد و جایی نمی‌نویسد):
```bash
npx wrangler secret put TELEGRAM_BOT_TOKEN      # توکن ربات
npx wrangler secret put CHALLENGE_SECRET        # یک رشته‌ی تصادفی طولانی؛ مثلاً خروجی: node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

۶. **(اختیاری) Issue در GitHub** — توضیح پایین. اگر می‌خواهید:
```bash
npx wrangler secret put GITHUB_TOKEN
```
و در `wrangler.toml` خط `GITHUB_REPO` را فعال کنید.

۷. **انتشار**
```bash
npx wrangler deploy
```
آدرس چاپ‌شده (مثلاً `https://chart-terminal-bugreport.<حساب‌شما>.workers.dev`) آدرس گیرنده است.

۸. **تست:** `https://<آدرس>/challenge` را در مرورگر باز کنید؛ باید یک JSON با `salt` و `difficulty` ببینید.

## وصل کردن برنامه‌ها به این آدرس

آدرس در زمان **ساخت** برنامه داخلش گذاشته می‌شود:

- **ساخت ویندوز و اندروید (روی همین کامپیوتر):**
  ```powershell
  $env:VITE_BUG_REPORT_URL = "https://<آدرس-گیرنده>"
  cd desktop; npm run dist:win                        # نصب‌کننده‌ی ویندوز
  cd ..\android; .\gradlew.bat assembleStandaloneRelease assembleClientRelease -PbugReportHost=<فقط-نام-دامنه>
  ```
  (برای اندروید standalone، `bugReportHost` همان نام دامنه‌ی بدون `https://` است تا برنامه اجازه‌ی اتصال به آن را داشته باشد؛ ابتدا `npm run build` از ریشه با همان متغیر.)
- **لینوکس (GitHub Actions):** در ریپو: Settings ← Secrets and variables ← Actions ← Variables ← یک متغیر به اسم `BUG_REPORT_URL` با همان آدرس بسازید.
- **سرور (Pi/PWA):** متغیر محیطی `CT_BUG_REPORT_URL` را روی سرور بگذارید تا صفحه اجازه‌ی اتصال به گیرنده را داشته باشد.

## گزینه‌ی ۴: Issue در GitHub یعنی چه؟

اگر `GITHUB_TOKEN` و `GITHUB_REPO` را بگذارید، علاوه بر تلگرام، Worker برای هر گزارش یک **Issue** در ریپوی خصوصی شما می‌سازد (با برچسب `bug-report`): عنوان = خط اول توضیح، متن = توضیح کاربر + اطلاعات تشخیصی. فایده‌اش:

- فهرست مرتب و قابل جست‌وجو از باگ‌ها، بدون اینکه در تاریخچه‌ی چت تلگرام گم شوند؛
- می‌توانید وضعیت بدهید (باز/بسته)، برچسب بزنید، به کامیتی که درستش کرده وصل کنید (`fixes #12`) و بعداً بفهمید چه چیزی کی درست شده؛
- پیوند Issue داخل پیام تلگرام هم می‌آید.

چیزی که **داخل Issue نمی‌رود**: عکس‌ها (API گیت‌هاب برای Issue آپلود عکس ندارد) و راه تماس کاربر. این دو فقط در تلگرام می‌آیند. علامت `@` هم خنثی می‌شود تا گزارش نتواند کسی را منشن کند.

**ساخت توکن:** GitHub ← Settings ← Developer settings ← Personal access tokens ← **Fine-grained tokens** ← Generate. فقط ریپوی `SepiNick/tradingview-clone` را انتخاب کنید، دسترسی **Issues: Read and write** (و فقط همین) بدهید، انقضا بگذارید (مثلاً ۹۰ روز). توکن را با `wrangler secret put GITHUB_TOKEN` وارد کنید؛ جای دیگری نگذارید.

## هزینه و محدودیت‌ها (برنامه‌ی رایگان Cloudflare)

- Workers رایگان: ۱۰۰٬۰۰۰ درخواست در روز، ۱۰ میلی‌ثانیه CPU برای هر درخواست، بدنه‌ی درخواست تا ۱۰۰ مگابایت (ما ۹ مگابایت را حد گذاشته‌ایم). هر گزارش دو درخواست است، پس سقف نظری ۵۰٬۰۰۰ گزارش در روز.
- KV رایگان: ۱۰۰٬۰۰۰ خواندن و **۱٬۰۰۰ نوشتن در روز**؛ هر گزارش ۳ نوشتن دارد، برای همین `PER_DAY=300` است. بالاتر از آن گزارش‌ها تا فردا رد می‌شوند. اگر روزی گزارش زیاد بود: برنامه‌ی ۵ دلاری Workers این سقف‌ها را برمی‌دارد.
- CPU: پازل را برنامه حل می‌کند و Worker فقط یک هش می‌گیرد؛ مصرف CPU هر درخواست در حد میلی‌ثانیه است.
- ارقام از مستندات Cloudflare گرفته شده؛ قبل از تکیه‌ی جدی، صفحه‌ی limits خودشان را هم ببینید.

## دسترسی از ایران

ارزیابی روشنی که بگوید `workers.dev` در ایران باز است یا بسته پیدا نکردم. گزارش‌های ۲۰۲۶ می‌گویند فیلترینگ ایران با SNI (نام دامنه) کار می‌کند و دامنه‌های پشت Cloudflare هم مسدود می‌شوند، پس روی باز بودنش حساب نکنید. راه‌های کاهش ریسک:

1. **ذخیره‌ی فایل:** اگر ارسال شکست بخورد، برنامه گزارش را به‌صورت فایل ذخیره می‌کند تا کاربر برایتان بفرستد. (انجام شده.)
2. **دامنه‌ی اختصاصی** روی Cloudflare به‌جای `workers.dev` (کمتر هدف فیلتر است).
3. **سرور خارج از ایران:** کد Worker یک ماژول ساده‌ی Fetch است و به‌راحتی روی Deno Deploy، Bun یا یک VPS هم اجرا می‌شود؛ فقط KV را باید عوض کرد.
4. گزارش‌دهنده‌هایی که در ایران هستند ممکن است با VPN گزارش بفرستند.
