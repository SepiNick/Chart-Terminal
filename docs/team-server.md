# سرور تیمی: حساب‌ها، ورود دومرحله‌ای (2FA) و پیدا کردن سرور در شبکه

برای تیم ترید که یک سرور مشترک (یک کامپیوتر، Raspberry Pi یا VPS) دارد و اعضا از برنامه‌ی ویندوز، مرورگر و برنامه‌ی اندروید وارد می‌شوند. این صفحه برای **صاحب سرور** است. جفت کردن گوشی برای هر عضو در [pairing.md](pairing.md) آمده است.

## ۱. حساب‌ها (سرور عمومی)

سرور تیمی یک **سرور حالت عمومی** است (`CT_MODE=public`، نگاه کنید به [docker.md](docker.md)): هر نفر نام کاربری و رمز دارد و تنظیمات، رسم‌ها، واچ‌لیست‌ها و هشدارهایش فقط مال حساب خودش است.

```bash
CT_MODE=public CT_PUBLIC_URL=https://charts.example.com CT_ADMIN=boss node index.ts   # در اولین اجرا یک رمز یک‌بارمصرف برای ادمین چاپ می‌شود
node cli.ts invite 5 7 "trading team"      # ۵ بار مصرف، ۷ روز اعتبار: کد را برای اعضا بفرستید
```

اعضا با کد دعوت ثبت‌نام می‌کنند (`CT_REGISTRATION=invite`، پیش‌فرض). سرور خصوصی (یک رمز، بدون نام کاربری) هم می‌تواند 2FA داشته باشد، بخش ۳.

## ۲. اجباری کردن 2FA

2FA یک کد ۶ رقمی از برنامه‌ی احراز هویت (Google Authenticator، Aegis، 1Password و ...) است: TOTP طبق RFC 6238، الگوریتم SHA-1، هر ۳۰ ثانیه.

| تنظیم | اثر |
|---|---|
| (پیش‌فرض) | **ادمین‌ها همیشه** 2FA دارند؛ اعضا خودشان انتخاب می‌کنند |
| `CT_REQUIRE_2FA=1` | **همه** باید 2FA داشته باشند |
| `CT_REQUIRE_2FA=0` | هیچ‌کس مجبور نیست (فقط برای محیط بسته‌ی آزمایشی) |

حسابی که باید 2FA داشته باشد ولی هنوز ندارد، **درست بعد از رمز درست** به مرحله‌ی راه‌اندازی می‌رود: QR را اسکن کند، اولین کد را بزند و ۸ کد بازیابی را نگه دارد. تا آن موقع هیچ نشستی ساخته نمی‌شود. اعضایی که مجبور نیستند می‌توانند از تنظیمات -> Security روشنش کنند (رمز و یک کد لازم است).

نکته‌ها:

- هر کد فقط **یک بار** پذیرفته می‌شود؛ کدی که قبلاً مصرف شده به درد نمی‌خورد. سرور کد گام فعلی و یک گام قبل و بعد را می‌پذیرد (اختلاف ساعت).
- بعد از ۱۰ کد غلط، حساب ۱۵ دقیقه قفل می‌شود (و همین‌طور نشانی شبکه)، حتی برای کد درست. بلیت ورود (۳ دقیقه، یک‌بارمصرف، وابسته به نشانی) بعد از ۵ کد غلط از بین می‌رود.
- راز **رمزنگاری‌شده** ذخیره می‌شود (AES-256-GCM؛ در سرور عمومی با فایل کلید `data/totp.key` که باید همراه داده‌ها پشتیبان بگیرید). کدهای بازیابی فقط به صورت هش ذخیره می‌شوند.
- گوشی گم شد: یکی از ۸ کد بازیابی (هرکدام یک بار). اگر کدی نمانده، صاحب سرور `node cli.ts reset-2fa <name>` را اجرا می‌کند (حساب بعد از آن فقط با رمز وارد می‌شود و اگر سرور 2FA را اجباری کرده، دوباره راه‌اندازی‌اش می‌کند).
- تا وقتی سرور 2FA را اجباری کرده، عضو نمی‌تواند خاموشش کند.
- هر ورود، خطا، مصرف کد بازیابی و تغییر در گزارش حسابرسی (audit) ثبت می‌شود.

## ۳. سرور خصوصی

سرور خصوصی (یک رمز) هم 2FA دارد: تنظیمات -> Security روی همان کامپیوتر. از آن به بعد هر دستگاهی که وارد شود، از جمله گوشی، رمز و کد می‌خواهد. `CT_REQUIRE_2FA` برای آن نیست (مخصوص سرور عمومی است).

## ۴. پیدا کردن سرور در شبکه

سرور خصوصی که Home network access دارد، هر ۲ ثانیه یک پیام کوتاه broadcast روی پورت UDP شماره‌ی **41771** می‌فرستد تا برنامه‌ی اندروید و ویندوز آن را در «Servers on this network» نشان دهند. پیام فقط شناسه‌ی سرور، نام، نشانی‌ها، نسخه، حالت و روشن‌بودن 2FA را دارد: نه نام کاربر، نه هیچ رازی.

- خاموش کردن: `CT_DISCOVERY=0` یا کلید مربوطه در تنظیمات -> Server & notifications.
- فقط روی **همان زیرشبکه** کار می‌کند: روترها broadcast را عبور نمی‌دهند و Wi-Fi مهمان با جداسازی دستگاه‌ها آن را می‌اندازد. در این حالت نشانی را دستی بزنید (یا QR جفت‌سازی را اسکن کنید).
- سروری که فقط روی همین کامپیوتر گوش می‌دهد هرگز نمی‌فرستد و سرور عمومی اصلاً نمی‌فرستد.
- اگر گوشی اصلاً به کامپیوتر نمی‌رسد، VPN کامپیوتر و قانون فایروال ویندوز در [lan-setup.md](lan-setup.md) را بررسی کنید.

## ۵. پاسخ‌های سرور (برای توسعه‌دهندگان)

```
POST /api/auth/login        -> { twofa: true, ticket }   (رمز درست، 2FA روشن؛ هنوز نه نشست و نه توکن)
                            -> { enroll: true, ticket }  (سرور 2FA را اجباری کرده و حساب ندارد)
POST /api/auth/login/2fa    { ticket, code | recovery, device? }  -> { ok, user, token? }
POST /api/auth/login/2fa/setup  { ticket }                        -> { secret, otpauth, qrSvg }
POST /api/auth/login/2fa/enroll { ticket, code, device? }         -> { ok, user, token?, recoveryCodes }
GET  /api/auth/2fa/status   -> { enabled, required, recoveryLeft }
POST /api/auth/2fa/setup    { password } -> { secret, otpauth, qrSvg }
POST /api/auth/2fa/enable   { code }     -> { ok, recoveryCodes }
POST /api/auth/2fa/disable  { password, code | recovery code }
```

بسته‌ی beacon: `{"ct":1,"id":"<16 hex>","name":"...","urls":["https://192.168.1.20:8443","http://192.168.1.20:8787"],"v":"<version>","mode":"private","twofa":false}`.
