# Competitor gaps: what was built and what was not

Source: the competitor report (2026-11-04). This document lists only the items from that report that turned into code. Each item says how it was tested.

| Complaint about competitors | What was built | How it was tested |
|---|---|---|
| TradingView: **repainting** indicators and over-optimistic backtests | A **Repaint check** button in the Pine editor (`src/pine/repaint.ts`). It runs the script for the last few candles once with all the data and once with data only up to one candle past each of them; any value that differs used the future. Plots, candle and background colors, and alertconditions are compared. | 4 tests: a normal indicator is stable, `lookahead_on` is caught and stays stable without lookahead, data from another symbol is cut off too, error and too little data |
| ATAS and NinjaTrader: multi-stage **Exit Strategy** (several targets, breakeven, trailing) | An **Exit plan** field in the order ticket (`src/exits.ts`, engine in `src/trading.ts`): `sl 2%; tp 1R 50%, 3R 50%; be 1; trail 1% 2`. Once the entry is filled, the stop loss and a ladder of targets are created; each target hit reduces the stop to the remaining position, moves it to breakeven, and it can trail. **Paper account** only. | 11 tests: parsing and errors, long and short, breakeven and offset, trailing that only tightens, stop loss before target, inexact splits, limit entry, saving and restoring the account |
| Everyone: **"no human support"** | A Diagnostics panel under 🔔 (`src/diagnostics.ts` and the route `GET /api/diag/sources`). A text report of the browser, the server, the response time of each data source, and the latest errors. Keys, tokens, passwords, emails, and IPs are stripped, and nothing is sent anywhere. | 4 sanitizing and report tests, 1 source-probe test, a route-classification test |
| ATAS and Bookmap: **steep learning curve** | A "Quick start" menu in ▦ Order flow: four ready-made views, each with a one-line explanation ("Who is pushing the price?", "Imbalance and absorption", "Where are the resting orders?", "Day value and structure") | 1 settings validity test |
| NinjaTrader and ATAS: **freezes and memory leaks** | `npm run bench`: run time of the heavy paths against a ceiling, and heap growth after 150 repetitions | Run: everything under the ceiling; heap growth 0.0 MB |
| **XSS** risk (158 `innerHTML`) | `npm run audit:html`: uses the type checker to inspect every string inside an HTML template that is not escaped. One real case (an axis value in the optimization heatmap) was escaped. | Run; the 220 remaining cases are recorded in `scripts/audit-html.baseline.json`. Two other places where data comes from a backup or the server (the journal's custom-field ID, the no-code input value) were hardened too |

## About the XSS audit: what was actually checked

The tool only says "a `string` entered HTML without `esc()`". It cannot tell whether the string came from the user or the server or is a constant. I read the files in their real context and checked every path through which user text, server data, or backup data enters the page: the journal (form, table, comparison, checklist, analyses), accounts and exchange error messages, the list of share links and devices, the calendar and news, alerts, AI, skill results, Pine script inputs (their IDs are generated by the app itself), the no-code form, the tester's forms and tables, and menus. All of them use `esc()`, except:

- the axis value of the optimization heatmap table (fixed),
- the journal's custom-field ID and the no-code input value, which can also come from a backup or the server (hardened).

What remains is the internal IDs and keys of the drawing tools, formatted numbers, fixed table labels, and SVG strings. I did not trace each of the 220 cases line by line; I read the categories in their real context. So the conclusion is "nothing was found on the paths where outside text enters", not "the whole app is safe". From now on, any new `${…}` that is not escaped turns `npm run audit:html` red. Before the public multi-user mode, an independent review (for example semgrep) is still needed.

## What I did not build (and why)

- **Signed installer and automatic updates:** it needs a signing certificate, and the choice of update source (GitHub) is up to you.
- **Exit plan for exchange testnet accounts:** the server's order model (`server/brokers/`) only has TP/SL. A ladder simulator on the server is a separate job and needs a trade-guardian review. The client explicitly rejects it.
- **Live repaint of the current candle:** as with TradingView's request.security behavior, seeing it requires a live feed, and `Repaint check` only catches lookahead.
- **A support team:** Diagnostics builds a report but nobody answers. The landing page still has to say this honestly.
- **A native mobile app and a community script library:** both are large and do not work without a separate plan.
