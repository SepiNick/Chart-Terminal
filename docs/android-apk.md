# اپ اندروید (APK) برای Chart Terminal

حالا **یک** اپ داریم (`app.chartterminal`، فایل `Chart-Terminal-<نسخه>-android.apk`) که جای دو نسخه‌ی قبلی (client و standalone) را گرفته. دو حالت دارد و با همان حالتی شروع می‌شود که آخرین بار استفاده کردید:

| حالت | چیست | صرافی‌ها و بروکرها |
|---|---|---|
| **محلی** (بدون سرور) | برنامه‌ی وب داخل APK است و همه‌چیز روی همین گوشی می‌ماند | **فقط Binance** |
| **سرور** | اپ، سرور Chart Terminal شما را تمام‌صفحه باز می‌کند | **هرچه سرور دارد** (همه‌ی صرافی‌ها و بروکرها مثل ویندوز)، هشدارهای سمت سرور، همگام‌سازی |

برای داشتن همه‌ی صرافی‌ها و بروکرها روی گوشی به یک سرور وصل شوید: برنامه‌ی ویندوز با روشن‌بودن *دسترسی شبکه‌ی خانگی*، رزبری پای یا VPS. راهنما: [lan-setup.md](lan-setup.md) (قاعده‌ی فایروال ویندوز هم همان‌جاست).

ارتقا: شناسه‌ی اپ همان شناسه‌ی client قدیمی است، پس روی آن نصب می‌شود و سرور ذخیره‌شده را نگه می‌دارد. اپ standalone قدیمی (`app.chartterminal.standalone`) اپ جداست و داده‌اش منتقل نمی‌شود؛ هرچه لازم دارید از آن خروجی بگیرید و بعد پاکش کنید.

## انتخاب سرور

منو را باز کنید (Back در صفحه‌ی اول، یا نگه‌داشتن گوشه‌ی بالا-راست) و **Servers...** را بزنید؛ صفحه‌ی سرورها در حالت محلی باز می‌شود.

- **سرورهای این شبکه**: سرورهایی که خودکار پیدا شده‌اند (بخش پیدا‌کردن خودکار). رویشان بزنید تا وصل شوید.
- **افزودن سرور** با آدرس، مثلاً `https://192.168.1.20:8443` یا `http://192.168.1.20:8787`. سرورهای ذخیره‌شده را می‌شود تغییر نام داد و حذف کرد.
- **Scan QR** / **Enter pairing code**: جفت‌کردن گوشی با سروری که روی کامپیوتر واردش شده‌اید؛ [pairing.md](pairing.md).
- **Use this device only (local mode)**: برگشت به برنامه‌ی داخلی.

روی سرور تیمی، سرور هر وقت لازم باشد نام کاربری، رمز و کد 2FA می‌خواهد: [team-server.md](team-server.md).

## پیدا‌کردن خودکار

سرور (حالت خصوصی با دسترسی شبکه‌ی خانگی، یا `CT_LAN`) هر ۲ ثانیه یک بسته‌ی UDP کوچک روی پورت **41771** پخش می‌کند. گوشی فقط وقتی صفحه‌ی سرورها باز است گوش می‌دهد. فقط روی همان زیرشبکه کار می‌کند؛ وای‌فای مهمان با جداسازی کلاینت‌ها، VPN روی گوشی یا کامپیوتر، و فایروال ویندوز جلویش را می‌گیرند. در آن حالت آدرس را دستی بزنید.

## منو

Back تا وقتی صفحه‌ای برای برگشتن هست برمی‌گردد؛ در صفحه‌ی اول منو را باز می‌کند: **Servers...**، Reload، Keep screen on (پیش‌فرض خاموش)، Exit.

## HTTP و HTTPS (امنیت)

- **HTTP ساده** فقط برای آدرس‌های شبکه‌ی خانگی مجاز است: `10/8`، `172.16/12`، `192.168/16` و `localhost`؛ هم هنگام وارد‌کردن آدرس و هم برای هر درخواست بررسی می‌شود. (`network-security-config` بازه‌ی IP را نمی‌فهمد، برای همین در کد انجام می‌شود.)
- **WebSocket**: `ws://` فقط به همین آدرس‌های خصوصی مجاز است؛ اسکریپتی که در هر صفحه تزریق می‌شود `ws://` به میزبان عمومی را رد می‌کند.
- **HTTPS**: اعتبارسنجی گواهی هیچ‌جا خاموش نیست. نسخه‌ی release فقط **CAهای سیستم** را قبول دارد، نه CA نصب‌شده‌ی کاربر. روی شبکه‌ی خانگی از `http://` یا گواهی معتبر عمومی استفاده کنید. نسخه‌ی debug CAهای کاربر را هم قبول می‌کند (CA را طبق `docs/lan-setup.md` نصب کنید و `Chart-Terminal-<نسخه>-android-debug.apk` را بگیرید).
- ناوبری هرگز از مبدأ فعلی بیرون نمی‌رود: لینک‌های دیگر در مرورگر سیستم باز می‌شوند.
- حالت محلی فقط به خود اپ و دو میزبان عمومی Binance (`data-api.binance.vision`، `wss://data-stream.binance.vision`) دسترسی دارد؛ بقیه بسته است.
- پل بومی `window.CTNative` (فهرست سرورها، پیدا‌کردن، تعویض حالت) فقط برای برنامه‌ی داخلی و سرور ذخیره‌شده هست، نه سایت‌های دیگر. دسترسی دوربین (اسکن QR) فقط به همین صفحه‌ها و فقط برای تصویر داده می‌شود.
- مجوزها: اینترنت، وضعیت وای‌فای و multicast (پیدا‌کردن خودکار)، دوربین (اسکن QR، بار اول پرسیده می‌شود).

## حالت محلی

برنامه‌ی ساخته‌شده (`dist/`) داخل `assets/www` بسته‌بندی می‌شود و از `https://appassets.androidplatform.net` سرو می‌شود (مسیر ناموجود و `/api/*` پاسخ 404 می‌گیرند؛ `..` و `\` رد می‌شوند). برنامه در شروع `GET /api/auth/status` را می‌زند؛ 404 یعنی حالت محلی: بدون ورود، نمودار و داده‌ی زنده مستقیم از Binance. داده در localStorage و IndexedDB همین WebView می‌ماند (با «Clear app data» یا حذف اپ پاک می‌شود؛ `allowBackup` خاموش است). قابلیت‌هایی که سرور می‌خواهند (هشدار سمت سرور، حساب بروکر، بازار غیر Binance، اخبار/تقویم، AI، فوروارد تست) با پیام غیرفعال‌اند.

## ساخت

پیش‌نیاز: JDK 17 و SDK اندروید (platform 35، build-tools 35.0.0)؛ مسیر SDK را در `android/local.properties` بگذارید (`sdk.dir=C\:\\Users\\<name>\\Android\\Sdk`).

```
npm run build:android            # dist/ را می‌سازد، داخل اپ می‌گذارد، release امضاشده (برای debug: npm run build:android debug)
# یا: npm run build ، بعد
cd android && gradlew.bat assembleRelease    # app/build/outputs/apk/release/Chart-Terminal-<نسخه>-android.apk
```

تسک Gradle با نام `syncWebAssets` پیش از هر ساخت `dist/` را در `android/app/src/main/assets/www` کپی می‌کند (در git نیست) و اگر `dist/` نباشد با پیام روشن می‌ایستد. بعد از هر تغییر کد وب دوباره `npm run build` لازم است (اسکریپت بالا خودش اجرا می‌کند).

امضای release از `android/keystore.properties` و `android/chartterminal.jks` خوانده می‌شود؛ هر دو در `.gitignore` هستند: **هرگز commit نکنید** و پشتیبان امن نگه دارید (بدون آن‌ها نمی‌توانید به‌روزرسانی با همان امضا بدهید). ساخت keystore تازه: `keytool -genkeypair -v -keystore chartterminal.jks -alias chartterminal -keyalg RSA -keysize 2048 -validity 10000`.

## CCXT مرورگری (فقط اندروید)

حالت محلی می‌تواند از طریق CCXT که داخل WebView اجرا می‌شود با صرافی‌هایی غیر از Binance هم کار کند. بسته‌ها را `npm run build:ccxt` (`scripts/build-ccxt-lite.mjs`، با `ccxt` و `esbuild` قفل‌شده در devDependencies) در `dist-ccxt/` (خارج از git) می‌سازد و `npm run build:android` آن‌ها را به‌صورت `ccxt/lite.js` (۳۷ صرافی منتخب (همه‌ی پیش‌فرض‌ها و همه‌ی ارائه‌دهنده‌های CCXT کاتالوگ)، ~۳٫۷ مگابایت خام / ~۷۴۰ کیلوبایت gzip. توجه: Hyperliquid فعلاً از فهرست پیش‌فرض کنار گذاشته شده است چون پروکسی بومی بدنه‌ی POST را عبور نمی‌دهد) و `ccxt/full.js` (همه‌ی صرافی‌های ccxt قفل‌شده، ~۶٫۱ مگابایت / ~۱٫۲ مگابایت gzip، برای مسیر «افزودن صرافی») داخل APK می‌گذارد. این فایل‌ها هرگز در `dist/` وب/دسکتاپ نیستند: اسکریپت فقط هنگام اجرای Gradle آن‌ها را در `dist/ccxt/` می‌گذارد و بعد پاک می‌کند. پس `gradlew assembleRelease` دستی بدون CCXT است، مگر اینکه پیش از آن `node scripts/build-ccxt-lite.mjs` را بزنید و `dist-ccxt` را در `dist/ccxt` کپی کنید.

قرارداد: اپ ابتدا `ccxt/lite.js` (اسکریپت کلاسیک ساده) را از `https://appassets.androidplatform.net/ccxt/` می‌خواند؛ این فایل `globalThis.ccxtLite = { <id>: ExchangeClass, ..., ids: [<id>, ...] }` را تعریف می‌کند. فقط وقتی شناسه‌ای آن‌جا نباشد (مثلاً «Add exchange») `ccxt/full.js` بارگذاری می‌شود که `globalThis.ccxtLite` را با یک ابرمجموعه‌ی هم‌شکل جایگزین می‌کند (`ccxtFull` جداگانه‌ای وجود ندارد)؛ «Add exchange» شناسه را پیش از ذخیره با `ccxtLite.ids` می‌سنجد. نمونه‌سازی: `new ccxtLite.binance({ enableRateLimit: true })`. شناسه‌هایی که نسخه‌ی قفل‌شده‌ی ccxt ندارد از بسته حذف می‌شوند (فعلاً هیچ)؛ `ccxtLite.ids` را ببینید. تست همچنین بررسی می‌کند که همه‌ی `DEFAULT_EXCHANGES` و همه‌ی شناسه‌های `ccxt` کاتالوگ در lite باشند. تست: `node --test scripts/build-ccxt-lite.test.mjs` (جزو `npm test`).

## نصب روی گوشی

نصب از منبع ناشناس را برای مرورگر یا مدیر فایل مجاز کنید و APK را باز کنید، یا با USB debugging: `adb install -r Chart-Terminal-<نسخه>-android.apk`.

## محدودیت‌ها

- APK اعلان Push ندارد؛ هشدارها روی سرورند و وقتی اپ باز است دیده می‌شوند. برای Push، PWA را روی HTTPS نصب کنید ([android.md](android.md)).
- دوربین (اسکن QR) صفحه‌ی امن می‌خواهد: حالت محلی یا سرور `https://`.
- همه‌ی گوشی‌ها/وای‌فای‌ها پخش پیدا‌کردن خودکار را اجازه نمی‌دهند؛ زدن دستی آدرس همیشه کار می‌کند.
